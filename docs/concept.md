# コンセプトとゴール

- **目的**: `alter-ego` が何を目指し、何を目指さないかを明文化する
- **対象読者**: SDK の採用を検討する開発者、意思決定者、コントリビュータ
- **前提知識**: アバター画像合成の一般的な概念（パーツ単位の組み合わせ、レイヤー合成）

## なぜ作るか

既存のアバター作成 SDK やライブラリは、多くの場合以下のいずれか（または複数）が固定されている。

- **描画方式**: Canvas 2D 限定、SVG 限定、特定 3D エンジン依存
- **UI フレームワーク**: React / Vue などに密結合
- **素材形式**: 特定の絵柄・データ構造前提
- **デプロイ先**: ブラウザ限定、サーバー生成不可

これらの制約により、「別のレンダラで出したい」「React ではなく Vue で使いたい」「サーバーサイドで PNG を書き出したい」といった要求のたびにフォークか別実装が発生していた。

`alter-ego` はこの再発明を終わらせるために、**コアを headless にし、描画・I/O・FW 統合をすべてプラグインに追い出す**方針で設計する。

## ゴール

| # | ゴール |
| --- | --- |
| G1 | 任意の UI/FW から呼び出せる（Vanilla / React / Vue / Svelte / Node.js …） |
| G2 | 任意のレンダラで描画できる（SVG / Canvas / WebGL / サーバーサイド画像生成 …） |
| G3 | 任意の素材形式を扱える（SVG / PNG / glTF / 独自フォーマット …） |
| G4 | アセット追加が「スキーマ編集 + ファイル配置」で完結する |
| G5 | コア本体の依存を最小化し、バンドルサイズを小さく保つ |
| G6 | 非同期アセット読み込みを前提とし、ネットワーク越しでも自然に扱える |

## 非目標（Non-Goals）

以下は `alter-ego` の責務に含めない。別プロジェクトや利用者側の実装に委ねる。

- **特定の絵柄・世界観の提供**: 公式アセットセットを同梱しない。パーツはユーザーが用意する
- **アバターエディタ UI の同梱**: スライダーやカラーピッカーなどの UI は提供しない（サンプルとして別リポジトリに置く可能性はあり）
- **認証・アカウント連携**: ユーザー管理・保存先の決定は SDK の責務外
- **3D 物理演算・高度なアニメーション**: 必要ならプラグインで対応
- **画像編集機能**: レタッチ・フィルタ・マスク編集などは対象外

## 想定ユースケース

- プロフィール画像ジェネレータ（Web アプリへの組み込み）
- チャット・コミュニティサービスのアバター機能
- ゲーム内キャラクターのカスタマイズ画面
- OGP / サムネイル画像のサーバーサイド生成
- 他サービス向けアバター出力（Exporter プラグインで別フォーマットへ変換）

## 設計の原則

1. **Headless first**: コアは描画も DOM も I/O も知らない
2. **Schema as source of truth**: アバター構成の真実はスキーマ JSON にある
3. **Plugin over config**: 挙動の差し替えは設定値ではなくプラグインで行う
4. **Async by default**: アセットアクセスはすべて Promise ベース
5. **Minimal core**: コアの依存を増やさず、機能はプラグインとして足す

これらの原則は以降のすべてのドキュメント（アーキテクチャ・スキーマ・プラグインガイド）の判断軸となる。
